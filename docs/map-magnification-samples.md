# 地图取景：限定矮图展开与高窄图 4:3

2026-09-15；正常地图比较基线为已验收的 `9bb95fd3ee348ede08237bf29dbabd91b5fd45fa`。
以下数值均指内部 1920×1080 渲染；外层窗口缩放仍另行执行。

## 适用范围与规则

根据引擎解析完成的原生 VR 分类，分类不随窗口大小改变：

- 横长矮图：内收后的高度不超过 540，宽高比至少 16:9。对应此前扫描的高倍率横长候选，
  本地 5,363 张地图中有 43 张。先用原有比例展开静态地形、建筑各动画帧的上下范围；
  完整可用高度仍不足时，才等比放大填满高度。宽度边界保持原生 VR。
- 高窄图：原生宽度不超过 1,280，且高度大于宽度，共 1,200 张。
  居中设置最大 4:3 有效画面，1920×1080 下为 (240,0)–(1680,1080)，左右各留 240。
  世界等比缩放，相机可继续纵向移动。底栏仍按完整窗口居中。
- 其余 4,120 张保留基线规则，不使用素材范围展开，也不强制 4:3。
  800×600 小房间、飞行地图、正常主城属于此类。

扫描数量包含链接地图及落脚点回退估算；运行时以引擎实际解析的边界判定。
不以 NPC、怪物、玩家、宠物、移动物件或无限重复的装饰背景计算地图尺寸。
原有世界投影继续统一作用于人物、装备和交互坐标；装饰背景、前景和 HUD 的既有分类保留。

素材范围来自加载期间的 Canvas 尺寸与原点，支持翻转、多帧和重复素材缓存。
新增两个入口在整个 321 点补丁事务中校验字节后安装。地图载入后只保留数值矩形，
不持有 COM 对象；不增加逐帧素材读取或 GPU 回读。
元数据读取失败时整个展开结果作废，横长矮图退回 1 倍留边，避免依据不完整素材过度放大。
仍保留原有 8 像素安全内收、整数相机范围及地板相机约束。

“三个门”的原生 VR 高 470，建筑/地形范围可扩展至 y=-422…336。
内收后可用高度由 454 增加到 742，因此所需倍率由 2.3789 降至 1.4555。
真正只有很少纵向素材的地图仍会有较大倍率，例如盗贼之窝约 2.7273；这是完整显示后
再补足高度的结果。没有人为补造缺失素材。

## 回归验证

- 4,126 张显式 VR 地图通过相机、取景边界和输入检查；另测奇数输出尺寸、极小边界和 4K。
- 2,221 张底部地形样本全部通过；与基线直接比较，其中 1,512 张正常地图的倍率、相机和
  裁剪结果完全相同。高窄图改用 4:3 后可滚动范围改变，地板约束生效样本总数为 185。
- 射手村、废弃都市的相机下限仍为 128、163；真实 GPU 底部空白采样仍从 200 降至 0。
- 元数据多帧、缓存引用计数、失败回退、切图和物件单独重载测试通过；物理坐标不被重写。
- 实际 GPU 验证装备附属层、负 Z 底栏、淡出取景保持、离开地图恢复完整视口，以及西海叉路背景拼接。
- 321 个 EXE 补丁点，64 组分辨率/布局、26 个快捷键、旧崩溃点、回滚与窗口位置恢复测试通过。
- 装饰背景 1.8 倍的强制原生线性采样仍有 24 个边界像素，基线代码同样如此；保留回归上限。
  默认原生点采样为零缝隙。此项不同于最终窗口整帧的线性放大，本次未更改该分支。

## 复现和游戏验收

运行 `tools/audit-map-scenery.ps1`、`tools/export-magnification-sample.ps1`，然后运行
`tools/test-map-magnification-native.ps1`。输出在 `out/map-scenery` 和 `out/world-native`。
可用脚本参数指定 Data、MapleLib、客户端及编译器目录。脚本只读游戏资源，测试窗口隐藏。
旧版图形对照可传 `-Baseline -ViewportSource <基线 WorldViewport.cpp 路径>`。

优先复测：

1. 横长矮图：270000000 三个门、270010000 神录的过去、270040000 破碎的回廊。
   观察柱顶/桥底是否比之前的留边版本显示更多，NPC 点击、宠物和装备是否一致缩放。
2. 高窄图：230000001 中央广场。确认 4:3 有效区域、左右等宽留边、纵向跟随以及完整底栏。
3. 正常对照：270010100 追忆之路1、100000000 射手村、103000000 废弃都市、230010400 西海叉路。
   核对原有倍率、地板相机、背景拼接和底栏弹出菜单。
