# 轻量窗口缩放

用户反馈真正全屏清晰流畅、GPU 占用较低，希望窗口也使用不依赖 CuNNy 的缩放。
本次将 `algorithm=linear` 优化为一张输入纹理、一个复制着色器和一次 GPU 双线性绘制，
跳过 CuNNy 着色器加载、2× 中间图像和 Lanczos 重采样资源。窗口仍复用原 HWND 和图形
设备，维持原有尺寸、鼠标映射、位置保存及 60 帧控制。

这属于普通 GPU 插值，并不能保证复现驱动或显示器在全屏时使用的同一个滤波器。
真正全屏继续使用游戏的原始 Present。新增日志会明确记录 `windowed=0`、回缓冲区、
设备显示模式和 `CuNNy=no`，避免仅凭视觉外观推断是否使用神经网络。

Direct3D [StretchRect](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-stretchrect)
支持驱动滤波复制；本机放大测试发现其采样位置与标准像素中心双线性参考存在偏差。
最终实现采用明确半像素对齐的绘制；1:1 的 Render 测试使用不带滤波的精确复制，
实际游戏窗口 1:1 也通过同一条窗口同步输出路径精确复制。

## 窗口显示同步候选修复

旧窗口路径从 DX8 转换参数继承 `D3DPRESENT_INTERVAL_IMMEDIATE`，并在提交前使用独立
的 60 帧计时器。它限制调用频率，却未将画面提交与显示刷新同步。这是当前首要嫌疑，
尚未通过最终显示帧时间证明是全部原因；全屏日志现在也补充原始 interval 参数供对照。

- 输出交换链改为 `D3DPRESENT_INTERVAL_ONE`，60 帧上限配合 60Hz 设备时取消软件等待，
  避免两个时钟叠加。1:1 窗口也使用同一交换链，不再落回立即提交。
- 用户显式设置低于刷新率的上限时保留计时器；`max_fps=0` 切换为无限制立即提交。
  未知刷新率或创建垂直同步交换链失败时保留软件限帧，并记录回退。
- 每秒检查设备报告的刷新率，实时修改上限时按需重建自己的交换链，不重置游戏设备。
  保留窗口位置、鼠标映射、内部 1080p 以及全屏原始呈现。
- 最小化、原始呈现、设备丢失及输出重建时清空统计，避免把这些已知暂停纳入下一段窗口
  数据。Present 的等待时间现在可能包含垂直同步等待，不能当作纯 GPU 计算耗时。

自动验证覆盖真实 DX8 代理的同步交换链创建、1:1、反复调整窗口、运行中 0/30/60
限帧切换、游戏状态和托管纹理保留、Reset 与最终 Release。策略检查覆盖 59/60Hz、
120Hz、较低上限、未知刷新率、同步不可用回退；这些策略检查不代表所有屏幕实机验收。
原有像素参考、资源与 GPU 回归继续运行。最终窗口滚动和复杂地图的流畅度仍需用户验证。
