# 洞穴前景贴边与背景视差

2026-09-17，接续统一人物大小修复 `405a6be`。

人物恢复 1 倍后，原有背景覆盖投影仍为内部高度 / 600（1080p 为 1.8）。
直接缩放整个投影也会放大相机引起的位移。艰苦洞穴最近背景的
rx 为 -60、-65、-70，因此最后一层的水平速度变成相机的 1.26 倍。

修复保留背景素材尺寸和分块间距，只补偿相机位移被放大的部分。
LoadBack 静态/平铺路径使用 `Ratio(center,100,100,rx,ry)`；每次绘制读取
原生 Gr2D center，为投影增加 `(1-scale)*center*(rx,ry)/100` 像素平移。
不改写原生向量或资源，绘制后恢复投影和视口。自动滚动类型 4～7
使用不同的时间向量路径，本次保持原行为。

`211042000` 前景 21～23 的 x 为 -852、-906、-835，rx=ry=-90，type=0。
它们靠近原生左边界 -1022。当可见宽度从 800 增加至 1920 时，
相机边界与 90% 跟随之间产生 `(1920-800)*(100-90)/200=56` 的额外内偏。
非重复、靠近地图侧边且 -100<rx<0 的前景使用这一差值向外补偿。
同一平面的上下拼块获得相同补偿，右侧方向相反。宽度不足 800、
居中装饰、循环平铺和 rx=-100 的世界附着前景不移动。

只保存图层 Z、x、rx、ry、type 等值元数据，无持久 COM 对象引用。
地图重载清空列表，切图淡出沿用旧场景；HUD 与 Buff 不参与。
原生地址和接口来自当前 BeiDou.exe 的 LoadBack：

- 0063D2F2：属性解析后，x=-78h、rx=-6Ch、ry=-70h、type=-68h。
- 背景 Z=BFFE0C00+index*1000；前景 Z=C0042360+index*1000。
- 0063DD61：静态/平铺向量 Ratio；Gr2D 全局槽 BF14EC。
- Gr2D get_center 槽 5Ch；向量继承 IWzSerialize，get_x/get_y 为 20h/28h。

## 验证

真实 PCOM/Gr2D GPU 测试构建与 LoadBack 同样的 origin/Ratio 向量，
采用原生绝对时钟推进动态依赖，分别读取相机移动前后的像素。
这不是自动登录游戏逐图游玩的验收。

- rx=-70、ry=-50：相机移动 (100,100)，未补偿为 (-126,-90)，修复后 (-70,-50)。
- 同一 60×40 素材仍覆盖 108×72，背景覆盖尺寸没有缩回。
- 洞穴左侧素材边界夹具：未补偿露出 31 像素，修复后为 0。
- 左边三片补偿一致、右侧镜像补偿、800/1280/1920 宽度和非目标前景排除通过逻辑测试。
- 53 组地图人物尺寸和 3 组 Buff 图形回归通过。
- 原生背景接缝、射手村/废弃都市地板、装备、HUD、淡出及窗口测试通过。
